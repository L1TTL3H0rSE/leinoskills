# leinoskills

Авторские skills для работы с кодом и контекстом проекта. Каждая папка в `skills/` — самостоятельный пакет [Agent Skills](https://agentskills.io/specification): `SKILL.md` и необходимые references. В общих инструкциях нет зависимости от API Codex, Claude Code или runtime Leino.

| Skill | Когда применять |
| --- | --- |
| [vue-nuxt-workflow](skills/vue-nuxt-workflow/SKILL.md) | Vue/Nuxt: читаемый control flow, composables, готовые UI-компоненты, async и браузерные проверки. |
| [scss-workflow](skills/scss-workflow/SKILL.md) | SCSS и Vue styles: проверенные токены, состояния, селекторы, Sass API и адаптивная раскладка. |
| [go-backend-workflow](skills/go-backend-workflow/SKILL.md) | Go backend: handlers и сервисы, context, ошибки, SQL/sqlc, контракты и focused tests. |
| [project-memory](skills/project-memory/SKILL.md) | Решения, вопросы и термины в документации проекта, доступные человеку и любому агенту. |

Vue, Go и SCSS содержат практические примеры. Имена API и ограничения Digiversity отмечены как специфика исходного проекта и не становятся требованиями для других проектов. В репозитории только собственные skills; системные и сторонние плагины сюда не копируются.

## Подключение

```sh
git clone git@github.com:L1TTL3H0rSE/leinoskills.git
cd leinoskills
node scripts/check.mjs
node --test scripts/install.test.mjs
```

Для чтения skills Node.js не нужен. Установщик и проверки используют Node.js 20+ и только стандартную библиотеку; устанавливать npm-зависимости не требуется.

Выбери каталог обнаружения skills своего агента:

- [Codex](integrations/codex.md)
- [Claude Code](integrations/claude-code.md)

Для другого агента, поддерживающего Agent Skills, скопируй целую папку нужного skill в его каталог обнаружения или подключи её тем же установщиком. References должны оставаться рядом с `SKILL.md`.

Установщик принимает явный путь и создаёт ссылки на `skills/<name>`: directory junction на Windows, directory symlink на macOS/Linux. Он не определяет провайдера, не меняет его настройки и не выполняет сетевых запросов. Клон должен оставаться на месте.

- `--dry-run` показывает действия без записи.
- Без `--replace` любой конфликт останавливает установку до первого изменения.
- `--replace` переносит прежние одноимённые папки или ссылки целиком в соседний `skills-leinoskills-backup-<timestamp>-<id>/`. Backup находится за пределами каталога обнаружения skills; остальные skills сохраняются.
- Повторный запуск для уже подключённых исходников возвращает `unchanged`.
- При ошибке создания ссылки установщик восстанавливает заменяемую папку, если её место свободно. Ранее созданные ссылки остаются; после устранения причины можно повторить команду. Путь backup сохраняется в выводе.

Запускай один установщик на каталог и не редактируй старые копии во время переноса. Для возврата прежней копии удали только соответствующую ссылку и перемести сохранённую папку обратно; не удаляй каталог исходников через ссылку.

## Обновление и правки

Правь исходники в этом репозитории: оба агента увидят один и тот же файл. `git pull --ff-only` обновляет уже связанные skills. Для добавленного skill повтори установку; после обновления открой новую сессию агента.

Общие правила и примеры хранятся в `skills/`, особенности подключения — в `integrations/`. Каждый skill работает отдельно: ссылки на ресурсы остаются внутри его папки. Обязательный процесс согласования, конкретные инструменты и архитектуру определяет целевой проект.

Перед commit выполни две команды проверки выше и `git diff --check`. Валидатор проверяет UTF-8/LF, локальные Markdown-ссылки, имена, описания и явные пути провайдеров в skills. Frontmatter здесь намеренно ограничен двумя полями: plain `name` и JSON-quoted `description`; это допустимое подмножество YAML, а не универсальный YAML parser.

Filesystem-тесты проверяют установку, сохранность копий, отсутствие записи в dry-run, повторный запуск и защиту от пересечения каталогов. Они не заменяют наблюдение за решениями модели в реальной задаче.
